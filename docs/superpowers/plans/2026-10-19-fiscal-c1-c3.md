# Fiscal C1–C3 — anúncio nunca fica sem push fiscal

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps usam checkbox (`- [ ]`).

**Goal:** fechar os 3 caminhos (auditoria Codex 19/10/2026) em que um SKU publicado no ML fica sem dados fiscais ou com vínculo SKU→anúncio errado.

**Architecture:** correções cirúrgicas em 3 edges + 1 helper compartilhado. Sem migration, sem tabela nova. Emenda curta no ADR-0135 (não é decisão nova: é o D-7/D-8/D-9 valendo nos caminhos esquecidos).

**Tech Stack:** Deno edge functions, vitest (`pnpm test <path>`).

**Spec:** auditoria `~/Desktop/revisao-fiscal-codex-2026-10-19.md` (achados C1, C2, C3) + ADR-0135 (D-7 gate, D-8 push pós-publicação, D-9 edição fiscal, D-10 semáforo).

## Global Constraints

- Falha de enqueue NUNCA desfaz publicação/UPDATE (spec §3 do ADR-0135): `try/catch` + `console.error`, igual a `publish-familia-ml/processar.ts:307`.
- Erro de leitura nunca degrada em silêncio para lista vazia/"sem item": lança (padrão `listarItensUP`).
- "Somente estoque" sem criação de variação continua SEM gate fiscal (spec §5.1).
- Nenhuma escrita direta em anúncio do ML fora do fluxo do app.

## Review Focus

1. Split com partição 0 ainda sem linha em `anuncios_externos` (só `familias.ml_item_id`) — SKU da partição 0 não pode virar órfão falso.
2. Família UP (tem `anuncios_externos_itens`) — comportamento idêntico ao atual; split só entra quando não há itens UP.
3. Produto de 1 anúncio Legacy (sem partição > 0) — fallback `familias.ml_item_id` intacto.
4. Edição fiscal com 0 versões publicadas — não enfileira nada, `pushEnfileirado=false`.
5. UPDATE UP em somenteEstoque — continua sem gate (UP preserva composição nesse modo).
